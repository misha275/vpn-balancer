# Что изменилось после первой сборки

Код собран Go 1.22 и 1.23, проверен `go vet`; sing-box 1.11.4 и PostgreSQL 16 использованы реальные.
Тестов 44 (юнит + интеграционные), проходят в том числе с `-race`.

## Исправления (вторая итерация, Docker)
- **Образ не собирался:** `go mod tidy` в Dockerfile подтягивал тестовые зависимости зависимостей, одна из них
  требует Go 1.25, а образ на Go 1.23. Теперь в проекте лежат готовые `go.mod` и `go.sum`, Dockerfile делает
  `go mod download` и собирает воспроизводимо (без tidy).
- Добавлен `smoke-test.sh`: сквозной тест с настоящим клиентом VLESS+Reality, failover, reload, перезапуском и
  `deluser` (описание в DOCUMENTATION.md, раздел 11a). Прогнан в Docker: все проверки и 44 Go-теста проходят.
- Добавлен `.dockerignore`.
- В `smoke-test.sh` добавлена предпроверка Reality без балансировщика (перебор сайтов-маскировок и отпечатков) и сбор конфигов шлюза и клиента для разбора. Добавлено после первого прогона на тестовом сервере, где клиент не проходил через шлюз (ошибка `REALITY: processed invalid connection`, причина выясняется).

## Исправления (первая итерация)
- **Один битый узел блокировал все обновления конфига** (`sing-box check` падал целиком). Теперь такой узел
  исключается и логируется, остальные применяются (`core.go: Apply/validNodes`).
- **Проверки во время reload засчитывались как сбои узлов** и могли вызвать ложный failover. Добавлен счётчик
  поколений конфига: результаты прерванных проверок отбрасываются, watchdog 5 с после reload не считает сбои.
- `block` outbound deprecated в sing-box 1.11 и удаляется в 1.13: заменён на rule action `reject`
  (без узлов трафик пользователей отклоняется, а не уходит напрямую).
- Токены подписок утекали в лог и Telegram через текст ошибок net/http; токен бота Telegram утекал в лог. Исправлено.
- Алерт «подписка не обновляется» срабатывал только на ровно 3-й сбой, теперь повторяется (не чаще раза в 6 ч).
- Алерт «все узлы недоступны» мог сработать до первой проверки узлов; теперь только когда все узлы проверены.
- Выбор лучшего узла при равных оценках был случайным (порядок map); теперь детерминирован.
- `fingerprint` зависел от порядка узлов/пользователей, что могло вызывать лишние reload.
- Гонка данных по `NodeState.Node` в watchdog.
- `forEach` с лимитом 0 навсегда блокировался.
- Парсер: неподдерживаемые транспорты молча становились «голым TCP», теперь узел отбрасывается; vmess+grpc терял
  serviceName; ss с percent-encoded userinfo и `host:port/` не разбирался; дубликаты в одной подписке; в ссылке
  пользователя пробел в имени превращался в `+`.
- Перезапуск балансировщика больше не ждёт скачивания подписок, если узлы уже есть в БД.
- Проверка конфига при запуске (плейсхолдеры `<...>` из config.example.yaml).

## Проверено на реальных компонентах

- Clash API: `PUT /proxies/proxy`, `GET /proxies/proxy`, `DELETE /connections`.
- pgx: несколько SQL-выражений в одном `Exec`, jsonb <-> `map[string]any`, batch, CopyFrom.

## Итерация 3: прогон на реальном тестовом сервере
- Сквозной тест `smoke-test.sh` прошёл на сервере целиком: 0 ошибок, 44 go-теста, реальный клиент VLESS+Reality через шлюз, failover (~11 с, 7 сбойных запросов), reload, рестарт, deluser, реальная подписка (9 узлов, 8 живых).
- Причина прежнего «REALITY: processed invalid connection»: на этом сервере Reality с `handshake_server: www.microsoft.com` не работал, а с cloudflare/apple/google/mozilla работал. Скрипт теперь сам подбирает рабочий сайт. Для боевого конфига проверьте выбранный `handshake_server` тем же способом (раздел про handshake_server в DOCUMENTATION.md).
- `SMOKE_SUB_PORT` меняет порт тестовой подписки (по умолчанию 18080), если он занят.
- Не проверено: боевой docker-compose.yml (bridge-сеть); качество реальных узлов (у части задержка 220–850 мс, джиттер до 740 мс).

## Итерация 4: страна выхода, фильтр-правила, подписка для пользователей
- **Страна выхода узла** (`geo.go`). Через каждый рабочий узел опрашиваются сервисы `geo_urls`, результат пишется в БД
  (`nodes.exit_country`, `exit_ip`). Узлы с выходом в `blocked_exit_countries` (по умолчанию RU UA BY CN IR SY KP TM CU MM)
  или с неизвестной страной не получают трафик пользователей: они не входят в селектор `proxy` в sing-box, не выбираются
  контроллером, не выдаются в подписке. Если текущий узел оказался «запрещённым», происходит failover. Алерт в Telegram.
  Проверки узла (tier1-3) продолжаются.
- **Никакого выхода через сам сервер.** Если допустимых узлов нет, трафик пользователей отклоняется (rule action `reject`),
  а не уходит напрямую. `default_action` принимает только `proxy` или `block`. Прямой выход возможен только по явному правилу `direct`.
- **Правила фильтра** (`filter.go`, `rules` в config.yaml): `*.ru`, `*.example.com`, `example.com`, `ads*.x.com`, CIDR/IP, `port:`,
  `keyword:`, `regex:`; действия `direct | block | proxy`; порядок сверху вниз, первое совпадение. По умолчанию всё идёт через
  балансировщик. Проверка правил при запуске, команда `bal check`.
- **Подписка для пользователя** (`subserve.go`): `GET /sub/<токен>`, первая строка балансировщик, затем все допустимые узлы с меткой
  измеренной страны. Токен у каждого пользователя свой (`users.sub_token`), защита от перебора, HTTPS (`sub_tls_*`).
  Узлы теперь хранят исходную ссылку (`nodes.link`).
- Первая перезагрузка sing-box, в которой появился допустимый узел, делается без паузы `min_reload_interval` (пока узлов нет, пользователи и так отклоняются).
- В `/status` и `/metrics` добавлены `exit_country`, `exit_ip`, `allowed`, `balancer_nodes_excluded_by_country`.
- `adduser` печатает ссылку на шлюз первой строкой, адрес подписки второй. Новая команда `check`.
- Сквозной тест дополнен: подписка пользователя, правила direct/block/proxy (по цепочке в Clash API), подмена страны выхода на RU
  (трафик должен прекратиться) и возврат, реальные узлы по странам.
- Не проверено: определение страны на ваших реальных узлах (кроме прогона на тестовом сервере), правила по IP при клиентах, шлющих имя сайта (ограничение описано в документации).

## Итерация 5: каждая ссылка отдельный узел, веб-панель, команды, настройки на лету
- `node_identity: link`: каждая ссылка подписки считается отдельным узлом (подписки с общими хостами-прокладками, но разными выходами). По умолчанию `endpoint`.
- `geo_blocked_ttl`: узлы из запрещённых стран перемеряются чаще («карантин до следующей проверки»).
- **Веб-панель** (`ui.html`, `api.go`): обзор, узлы, настройки, пользователи. Вход по токену из `balancer token`, слушает `http_listen`.
- **Команды** (`cli.go`): status, nodes, node, switch, unpin, refresh, recheck, users/adduser/deluser/enableuser/sub, get/set/reset, rules, countries, subs, token, check, help.
- **Настройки на лету** (`settings.go`): 10 ключей хранятся в БД, перекрывают config.yaml, применяются за ≤10 с атомарно с проверкой. Ручное закрепление узла (`switch`/`unpin`).
- Тесты: настройки, API (токен, лимит неверных попыток), закрепление. В сквозной тест добавлен блок 8d (панель, API, команды, правила на лету): 142 проверки, 0 ошибок в песочнице.
- Не проверено: внешний вид панели в разных браузерах; панель без TLS.
- Прогон на реальной подписке (108 ссылок, link-режим): после полного цикла проверок 102 реальных узла живы; измеренные выходы DE 26, FR 21, NL 20, SE 19, FI 16, US 6, RU единицы. Все выходы RU исключены из трафика, в подписку пользователя попадают только допущенные. Выходных IP всего 6: у большинства хостов-прокладок один выход, а у одного хоста разные ссылки дают FI и US. Метки провайдера не всегда совпадают с реальным выходом, поэтому в подписке стоит измеренная страна.

## Итерация 6: установщик
- `install.sh`: самораспаковывающийся установщик (install, update, status, uninstall [--purge], extract). Ставит Docker, генерирует ключи Reality и пароль БД, подбирает handshake_server реальной проверкой Reality, пишет конфиг, собирает, запускает, создаёт первого пользователя, ставит команду `vpnb`.
- Пустой список подписок больше не ошибка конфигурации (предупреждение в логе): систему можно запустить и добавить подписку командой `subs add` или в панели.
- Проверено в песочнице: установка с нуля, `update` с сохранением конфига и пользователей, `uninstall --purge`. Установка Docker и ufw на реальном чистом сервере не проверялась.
- Скорость (tier3) теперь меряется только у допущенных узлов: узлы из запрещённых стран больше не занимают места в top-N.
