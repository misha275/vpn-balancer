## Итерация 4: страна выхода, фильтр-правила, подписка для пользователей
- **Страна выхода узла** (`geo.go`). Через каждый рабочий узел опрашиваются сервисы `geo_urls`, результат пишется в БД
  (`nodes.exit_country`, `exit_ip`). Узлы с выходом в `blocked_exit_countries` (по умолчанию RU UA BY CN IR SY KP TM CU MM)
  или с неизвестной страной не получают трафик пользователей: они не входят в селектор `proxy` в sing-box, не выбираются
  контроллером, не выдаются в подписке. Если текущий узел оказался «запрещённым», происходит failover. Алерт в Telegram.
  Проверки узла (tier1-3) продолжаются.
- **Никакого выхода через сам сервер.** Если допустимых узлов нет, трафик пользователей отклоняется (rule action `reject`),
  а не уходит напрямую. `default_action` принимает только `proxy` или `block`. Прямой выход возможен только по явному правилу `direct`.
- **Правила фильтра** (`filter.go`, `rules` в config.yaml): `*.ru`, `*.example.com`, `example.com`, `ads*.x.com`, CIDR/IP, `port:`,
  `keyword:`, `regex:`; действия `direct | block | proxy`; порядок сверху вниз, первое совпадение. По умолчанию всё идёт через
  балансировщик. Проверка правил при запуске, команда `bal check`.
- **Подписка для пользователя** (`subserve.go`): `GET /sub/<токен>`, первая строка балансировщик, затем все допустимые узлы с меткой
  измеренной страны. Токен у каждого пользователя свой (`users.sub_token`), защита от перебора, HTTPS (`sub_tls_*`).
  Узлы теперь хранят исходную ссылку (`nodes.link`).
- Первая перезагрузка sing-box, в которой появился допустимый узел, делается без паузы `min_reload_interval` (пока узлов нет, пользователи и так отклоняются).
- В `/status` и `/metrics` добавлены `exit_country`, `exit_ip`, `allowed`, `balancer_nodes_excluded_by_country`.
- `adduser` печатает ссылку на шлюз первой строкой, адрес подписки второй. Новая команда `check`.
- Сквозной тест дополнен: подписка пользователя, правила direct/block/proxy (по цепочке в Clash API), подмена страны выхода на RU
  (трафик должен прекратиться) и возврат, реальные узлы по странам.
- Не проверено: определение страны на ваших реальных узлах (кроме прогона на тестовом сервере), правила по IP при клиентах, шлющих имя сайта (ограничение описано в документации).

## Итерация 7: бесшовные обновления
- **Шлюз** (`gateway.go`): TCP-фронт на 443 + экземпляры sing-box по схеме blue/green. Новая конфигурация запускается рядом, новые подключения идут на неё, открытые доживают на старой (до `drain_timeout`). Не запустившаяся конфигурация отклоняется, старая продолжает работать. Падение sing-box лечится сторожем.
- **Отдельный контейнер `gateway`** (`balancer gateway`, `gateway: external`): контроллер обновляется и перезапускается без обрыва соединений. Шлюз помнит последнюю конфигурацию (после своего перезапуска сам возвращает её). Контроллер после перезапуска принимает уже работающую конфигурацию (`core: the gateway already runs this configuration`), если она совпадает по отпечатку.
- Отзыв доступа (пользователь, текущий узел, новое правило block) обрывает старые соединения через `drain_urgent`; обычные изменения нет.
- Пароли проб и секрет API выводятся из ключа Reality, поэтому не меняются при перезапуске контроллера. Порты sing-box выбирает шлюз.
- `install.sh update` обновляет только контроллер; `update --gateway` перезапускает шлюз (обрыв 2-5 с); старая установка с одним контейнером переводится на шлюз при первом `update`. Состояние шлюза: `vpnb status`, панель, `/api/overview`.
- Тесты: открытое соединение переживает переключение, срочное переключение обрывает его, сломанная конфигурация отклоняется, перезапуск упавшего sing-box, принятие работающего шлюза новым контроллером. Сквозной тест: 110-секундный поток через клиента не обрывается ни при смене конфигурации, ни при перезапуске контроллера; перезапуск контейнера шлюза.
- Не проверено: производительность фронта на больших потоках (используется копирование TCP на Go).

## Итерация 8: статистика и консоль, отпечаток ссылок
- **Отпечаток TLS в ссылках**: настройка `reality.fingerprint`, по умолчанию `ios` (было жёстко `chrome`). Факт: на реальном сервере v2rayNG с `chrome` не подключался (`REALITY: processed invalid connection`, хотя ключи, short id и SNI верны), с `ios` заработало. Вероятная причина (не проверена отдельно): свежий Xray при `chrome` шлёт постквантовое приветствие (X25519MLKEM768), которое Reality-сервер sing-box 1.11.4 не распознаёт.
- **Статистика** (`stats_gw.go`, `stats.go`, `sysinfo.go`, `logring.go`): шлюз считает байты каждого подключения и определяет пользователя по логу sing-box; контроллер каждые 5 секунд снимает процессор, память, диск, нагрузку и трафик, хранит историю для графиков (память и таблица `metrics`) и пишет трафик пользователей по часам (`traffic_hourly`) и последнюю активность (`user_seen`).
- **Панель**: вкладки «Сервер» (карточки и 6 графиков, периоды 1 ч / 6 ч / 24 ч / 7 дней), «Клиенты» (онлайн, скорость, трафик, адреса, открытые соединения, неопознанные подключения), «Консоль» (контроллер и шлюз, фильтр, скачивание). Команды `stats` и `logs`, API `/api/stats`, `/api/stats/history`, `/api/logs`.
- Подключения, не прошедшие Reality, больше не заполняют лог по строке на каждое: сводная строка раз в 30 секунд с адресами.
- Тесты: учёт пользователей по строкам лога, неопознанные и невалидные подключения, кольцо логов, разбор /proc, уплотнение точек графика, база (суммы за окна, последняя активность, представление), шлюз в отдельном контейнере (статистика и консоль через API), полная цепочка с настоящим sing-box (клиент → шлюз → пользователь alice: байты, онлайн-сессия). В сквозной тест добавлена проверка статистики, истории, консоли, команд и отсутствия адресов назначения в логах.
- Ограничения: «сеть» это трафик клиентов через шлюз, а не счётчик сетевой карты; трафик считается по внешнему слою (на несколько процентов больше полезных данных); соединение, оборвавшееся за 1,5 с до появления имени в логе, попадает в «оборвались до определения пользователя»; копирование на стороне клиента идёт через счётчик, без splice (влияние на скорость больших потоков не измерялось).


## Итерация 9: качество узлов, удаление пользователей, диагностика
- Время последней проверки и последние 3 замера скорости с датой и временем хранятся в базе (переживают перезапуск и обновление подписок), показываются в панели («старое · дата»), в `vpnb nodes` и `vpnb node ИМЯ`.
- Скорость влияет на выбор: два последних замера ниже `min_speed_kbps` (по умолчанию 8 Мбит/с) - узел не выбирается, а если пользователи на нём, они переводятся на хороший. Если все узлы медленные, берётся лучший из них (без узла не остаёмся никогда). Один низкий замер - только повод перемерить.
- Тест скорости: приоритет текущему узлу, подозрительным, ни разу не измеренным и устаревшим; свежий замер не повторяется (экономия квоты провайдера). `tier3_interval` по умолчанию теперь 10 минут.
- Проверка сервисов (Telegram, YouTube, X/Twitter, TikTok, Instagram, Facebook, WhatsApp, Discord, Google, GitHub, OpenAI, Spotify, Netflix): список редактируется в настройках. Telegram проверяется ещё и прямым TCP к его серверам (именно так не открывался Telegram при рабочем интернете). Обязательные сервисы (`required_services`, по умолчанию telegram): два прохода подряд неудачно - узел исключается, пока есть другие. Остальные сервисы снижают оценку на 3 балла за сервис.
- Пользователей можно удалить навсегда: кнопка «Удалить», `vpnb rmuser ИМЯ`, `DELETE /api/users/ИМЯ`. «Отключить» осталось для временного отключения.
- Консоль ошибок пользователя: «Клиенты» → «Диагностика», `vpnb logs user ИМЯ`. Только ошибки соединений и адреса, заблокированные правилами; обычные соединения не записываются.

## Режимы балансировщика, подписки и QR (итерация 11)
- Три режима на одном порту: текущий, лучшая скорость, лучший пинг (`modes.go`, `checker_modes.go`): отдельные ключи пользователя, селекторы sing-box `proxy`, `proxy-speed`, `proxy-ping`, копия правил фильтра для каждого режима.
- Подписки: `/sub/<токен>/balancers` (только балансировщики) и `/sub/<токен>` (балансировщики + все серверы). В панели QR для каждой ссылки (`/api/qr`).
- Отпечаток TLS в ссылках по умолчанию `firefox` (раньше `ios`); установщик заменяет `ios` на `firefox` в config.yaml при обновлении.
- Учёт: трафик и ошибки режимов складываются на пользователя, у сессии есть режим. В имени пользователя запрещён `~`.
- Тесты: выбор узла режимами и гистерезис, сборка конфига, сквозной на настоящем sing-box, подписки, QR.

## Итерация 14 (версия 3.2.0; предыдущая была 3.1.0): внешние серверы, режимы «ссылка / через основной сервер», категории
