# VPN-балансировщик (шлюз): Go + sing-box + PostgreSQL

Пользователь подключается к одному постоянному адресу (VLESS+Reality). За ним контроллер
держит пул из сотен узлов из подписок, постоянно проверяет их и переключает выход на лучший.

Подробная документация: [DOCUMENTATION.md](DOCUMENTATION.md). Сквозной тест на сервере: `bash smoke-test.sh` (см. раздел 11a).

## Быстрая установка
`sudo bash install.sh` (или `-y --sub АДРЕС`): один файл ставит Docker, ключи, конфиг, запускает систему и печатает ссылку и токен панели. Подробно: раздел 3.0 документации.

## Запуск вручную
1. `cp config.example.yaml config.yaml`, `cp .env.example .env`, поменяйте пароль в `.env`
   (только буквы и цифры, например `openssl rand -hex 16`: пароль входит в URL, спецсимволы его ломают)
   и подставьте тот же пароль в `database_url`.
2. Ключи Reality:
   `docker run --rm ghcr.io/sagernet/sing-box:v1.11.4 generate reality-keypair`
   `openssl rand -hex 8` (short_id). Впишите в `config.yaml`, укажите свои подписки и `public_host`.
3. `docker compose up -d --build`
4. Пользователь: `docker compose exec balancer balancer -c /etc/balancer/config.yaml adduser alice`
   (печатает vless:// ссылку для клиента). Также команды `users` и `deluser NAME`.
5. Панель и команды: `ssh -L 8080:127.0.0.1:8080 root@сервер`, браузер `http://127.0.0.1:8080/`, токен `balancer token`; `balancer help` печатает все команды (раздел 6c документации).
6. Состояние: `curl 127.0.0.1:8080/status`, метрики Prometheus: `127.0.0.1:8080/metrics`.

## Статистика
Панель: вкладки «Сервер» (процессор, память, диск, сеть, графики), «Клиенты» (кто онлайн, скорость, трафик по пользователям) и «Консоль» (логи). Те же данные: `vpnb stats`, `vpnb logs`. Раздел 6e документации.
Ссылки пользователей выдаются с отпечатком TLS `ios` (`reality.fingerprint`): с `chrome` свежие клиенты Xray не проходили проверку Reality.

## Обновления без разрыва
Шлюз (то, к чему подключаются пользователи) работает в отдельном контейнере. `sudo bash install.sh update` обновляет контроллер, не трогая открытые соединения;
смена узлов, пользователей и правил тоже идёт без обрыва (новая конфигурация поднимается рядом со старой). Подробно: раздел 6d документации.

## Как работает
- Подписки (base64 или список ссылок: vless, vmess, trojan, ss, hysteria2) скачиваются раз в `sub_refresh`.
  Если подписка недоступна, её узлы остаются в пуле ещё `node_grace`.
- Tier 1 (1 мин): TCP-подключение. Tier 2 (3 мин): реальные HTTPS-запросы через каждый узел к нескольким
  сайтам. Tier 3 (45 мин): замер скорости у топ-5. Оценка = успешность, задержка (EWMA), джиттер, скорость.
- Текущий узел проверяется каждые 5 с; два сбоя подряд дают мгновенный failover и сброс соединений.
- Гистерезис: лучший узел должен быть лучше на 15% три цикла подряд, иначе переключения нет.
- Мёртвые узлы уходят в карантин с растущей паузой (1...30 мин).
- Если у самого сервера нет интернета, результаты проверок отбрасываются и переключений не происходит.
- sing-box запускается как дочерний процесс с watchdog; конфиг проверяется `sing-box check` перед перезагрузкой.
- Если `sing-box check` отвергает отдельный узел из подписки (например, неизвестный шифр), узел исключается и
  пишется в лог, остальные применяются. Ошибка не в узле (ключи Reality, порт) остаётся ошибкой.
- Проверки, прерванные перезагрузкой sing-box, не засчитываются узлам как сбои.
- Узлы с неподдерживаемым транспортом (xhttp, kcp, quic, tcp+HTTP-обфускация) и ss с plugin отбрасываются при разборе.

## Тесты
`go test ./...` без окружения выполняет юнит-тесты (парсер ссылок, оценка узлов, гистерезис, выбор узла, конфиг);
интеграционные пропускаются. Полный прогон (нужны бинарник sing-box и PostgreSQL):

    SINGBOX_BIN=/usr/local/bin/sing-box \
    TEST_DATABASE_URL=postgres://balancer:PASS@127.0.0.1:5432/scratch \
    go test -race ./...

`TEST_DATABASE_URL` должен указывать на **отдельную** пустую базу: тесты делают TRUNCATE таблиц.
Сквозной тест поднимает два настоящих процесса sing-box (upstream shadowsocks и сам шлюз) и проверяет
проверку через конкретный узел, переключение через Clash API, reload и failover.

## Ограничения
- Все пользователи выходят через один общий лучший узел (не по одному на пользователя).
- Добавление/удаление пользователей и смена состава узлов перезагружает sing-box (соединения рвутся на пару секунд).
  Перезагрузка не чаще `min_reload_interval` (2 мин).
- Не разбираются форматы Clash YAML / sing-box JSON и протоколы tuic/wireguard.
- Порт 8080 без авторизации: держите на localhost или закройте прокси с паролем.
